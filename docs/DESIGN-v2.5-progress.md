## 最小変更案

| 工程 | 表示 | 観測点 |
|---|---|---|
| 準備・入力変換 | 工程名＋経過時間（%なし） | 既存の実行状態 |
| 高解像度化の推論 | 完了/総チャンク＋工程内% | 既存tqdm |
| 動画デコード | 完了/総デコードブロック＋工程内% | 上流VAE2.2の各ループ完了後 |
| デコード後処理 | 工程名＋経過時間（%なし） | unpatchify、正規化、uint8化の前後 |
| 中間動画保存 | 工程名＋経過時間（%なし） | 既存write_video呼び出しの前後 |
| 最終MP4作成 | 出力済み/対象フレーム＋工程内% | FFmpeg progress |
| 出力確認 | 工程名＋経過時間（%なし） | 既存workerの結果確認 |
| 完了 | 完了・再生・保存リンク | DBのsucceededを確認後のみ |

- VAEループのCPU転送・連結が済んだ位置で、ブロック完了イベントをflush付きでログ出力する。初回0/総数、最終回完了は必ず出す。最大毎秒程度にまとめ、GPU同期・追加デコード・テンソル複製は行わない。
- 既存上流ファイルへ最小のログ計測パッチを当てる。モデル、分割方法、計算結果、保存処理は変更しない。
- 例：`REFINER_PROGRESS {"phase":"decoding","completed":60,"total":95,"unit":"blocks"}`。総数はその実行のループから得る。固定値や動画秒数からの推定を使わない。
- collectorはDockerログのstdout/stderrを受信順でまとめて解析し、後の工程を古いtqdm表示で上書きしない。旧ログ形式にも対応する。
- APIに工程内のcompleted/total/unitを追加し、既存の進捗表示を拡張する。終了コードやジョブ状態の判断は既存実装が正本。

## 表示例と誤表示防止
```
動画デコード中  60 / 95 ブロック（この工程の63%）
推論：完了　動画化：処理中　保存：未完了
経過：8分12秒
```

- 全体の%・残り時間は出さない。工程ごとの所要時間を測っていないため、工程数の等分や過去の時間で数値を作らない。
- デコード100%でも、その後の処理や保存完了を意味しない。次の工程名へ移る。
- FFmpegが全フレームを書いても、プロセス終了と既存出力確認までは「完了」にしない。音声処理・faststart待ちが残る場合はその旨を表示する。
- 数値を取れない工程はスピナーと経過時間。計測のために動画保存ループを書き換えたり、新しい進捗基盤を作ったりしない。
- collectorの読取時刻と最後の進捗変化時刻を区別する。同じログの再読込で「進んだ」と扱わない。長い単一処理では変化がなくても異常・停止と断定しない。
- 進捗取得に失敗しても動画処理を止めない。古い数値には最終更新からの経過を添え、現在の工程名を隠さない。
